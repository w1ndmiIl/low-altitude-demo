# 地面起降、柜点交接与消防响应

当前实时演示由 `ground-operations.js` 扩展原运营模型，全部20架航空器从地面站点或平台开始。原202次固定配置实验继续使用原巡航模型，实时演示的路线和耗时另作功能验证。

## 演示操作

1. 打开Demo，选中U02外卖机，点击“跟随”。初始在地面装载，柜体落在地面，起降垫与柜体之间留出交接空间。
2. 开始运营：装载后准备起飞，实际高度逐步增加；到巡航高度后水平飞行。到达目标后下降，落地才开始入柜服务，完成后返场降落。
3. 重置后点击“楼宇火情”。应急按钮会自动开始运营；保持“新事件自动聚焦”勾选，镜头会跟随地面待命的U06。1×观察起飞，8×观察到场、侦察、投放及返場。手动暂停会同时冻结运动与任务时间。
4. 发布人员转运或跨江急送，观察平台起飞、场站/航路排队、降落交接。跨江急送仍需空中服务完成与地面车辆到位同时满足。

地面跟随视角自动靠近并趋于俯视，避免高楼遮挡交接点。拖动退出跟随，仍可平移、旋转和缩放。

## 状态和实际高度

| 阶段 | 模型行为 | 完成条件 |
|---|---|---|
| 地面待命 / 装载 | 占用独立泊位，柜点装载或接运 | 服务计时完成且安全状态允许 |
| TAKEOFF | 起飞准备2s，再逐步爬升；不水平推进 | 到达巡航高度且拥有必要场站资源 |
| FLYING | 后台规划，沿安全航路连续运动 | 到达当前航段目标 |
| LANDING / HOLD_LANDING | 申请降落位，逐步下降；占位时等待 | 达到地面/平台高度或火场作业高度 |
| SERVICING | 落地柜点交接、平台接运或空中现场作业 | 服务时间完成；暂停、异常不能假记完成 |
| 返场 | 内部返场航段、爬升或起飞、巡航、降落 | 在起降点落地后待命或补能 |

飞行参考高度与可视机体高度分开：地面参考点为0.6m，即起降垫顶面；重型平台参考点为10.6m。机体按起落架偏移放置，脚部接触平台。柜体底面为0m。地面装载/投递时有物资箱移动动画，尚未取件与已交付阶段不显示悬挂载荷。

无人机垂直速度6m/s、巡航120–195m；直升机垂直速度8m/s、巡航240/280m；eVTOL垂直速度8m/s、巡航220/260m。参数是课程设定。实际高度由航空器状态保存，水平A*仍使用保守120m障碍图，不在每次爬升时重新创建城市或重规划所有飞机。

## 站点、容量与安全

地面站点在原任务点附近搜索，按建筑完整多边形轮廓而非仅网格中心检查净空，排除水域，优先避开地面机动车道。真实道路、建筑和水域保持原数据；柜体、平台与消防站是新增仿真设施，不能当作钱江世纪城真实设施位置。

独立泊位记录实际占用者，飞机离开起降柱并移动超过60m后释放。100m内的进场飞机提前申请泊位，避免在同一垂直柱上相向起降。直升机站点按20m安全半径留出距离；重型公共交接点也采用足够的物理间距。场站放行资源与独立泊位分别管理，三个大型场站及跨江航路仍按容量1排队。

每0.05s检查起降通道：先求相对高度落入垂直保护区的时间区间，再在该区间求相对水平距离最小值。起降与水平运动会实际让行，不能把独立巡航层当成垂直过程的安全保证。该检查没有构成完整三维路径搜索或真实空管。

调度能源预算新增简化垂直起降耗能；后续水平航程仍为距离估计。若候选在地面且预算不足，进入20s教学补能，补能后重新参与调度，避免永久等待。已落地机遇失联/导航异常冻结交接；低能源保存剩余服务并补能，不能在未完成交接时统计成功。已装载物资锁定在原机上，避免抢占后由另一架机跳过装载。

## 消防响应

U06保留消防能力并从地面待命，日常配送不占用它。火情发布后进入真实任务队列，经能力、能源与路径检查派单。手动按钮在暂停状态自动启动；正常“暂停运营”仍可暂停演示。

流程为：地面起飞 → 航路飞行 → 下降至安全观察高度 → 侦察3s → 模拟消防投放7s → 火势指标降为零 → 返场爬升与降落。到达水平坐标不等于进入现场作业；降至作业高度后才记录到场，处置服务完成才统计业务完成。消防水流、火焰与烟气随作业阶段显示，是效果与状态模型，未模拟真实灭火能力。

## 验证与数据口径

`tests/ground.test.js`检查地面/平台初始化、渐进爬升与暂停、外卖落柜和返场闭环、消防各阶段、地面故障/补能、完整五类应急和起降三维扫掠。

`tests/browser-ground.cjs`验证当前默认Worker地面模式、火情按钮自动启动/跟随、实际起降与交接截图、1200s完整自动剧本、桌面首屏、移动布局及离线加载。结果保存在 `results/ground-execution-validation.json`、`output/playwright/ground-browser-check.json`。原八套流程验证固定基准，后台规划专项在固定巡航机队上验证；地面模式单独验证，重复检查不增加原202次实验配置数。

导出增加 `grounded_execution`、实际高度、`cruiseAltitude`、`onGround`、任务阶段、柜点/平台设施与返场落地记录。内部返场航段不增加配送或应急完成数。

当前仍是运动学、调度与状态仿真；未加入气动飞控、真实定位误差、完整三维航路、真实充电曲线或真实消防流体。
