# 前端与调度展示优化（2026-10-03）

城市画面是核心，右侧为辅助说明。桌面调度讲解沿用原任务栏的宽度：一般窗口290px，大屏335px；在1280px及以上窗口，左侧占两列总宽度的至少75%。平板适当换行，手机上下排列。

## 查看一次调度

1. 打开Demo，点击城市画面上方的“调度讲解”。运行中的仿真会暂停，当前派单记录冻结。
2. “任务入队”显示真实优先级与检查前的剩余队列。
3. “约束筛选”显示全部航空器和首个拒绝原因。左侧青色圈表示可选机，灰色点表示未通过者。
4. “代价比较”显示当前航段的航路代价、场站惩罚、抢占惩罚，以及当时能源和任务预算。点左侧候选按钮或右侧编号可以跟随飞机，回放仍保持原记录。
5. “派单结果”说明为什么中选或为什么保留队列。点击“继续观察执行”，返回现场并继续真实仿真。

讲解栏可以发布“人员转运”“客运排队”“物资救援”真实任务。前两个适合讲能力匹配与候选不足；物资救援能否抢占取决于当时机队阶段。所有结果均来自实际调度，未固定赢家。

任务选择器切换被讲解的任务；记录选择器可以查看同一任务的初次检查和近期变化。关闭讲解保持暂停，点击执行才继续；讲解栏内Esc返回现场。2D和3D使用同一记录与场景提示。

## 展示含义

调度器先按策略排队，再依次检查航空器状态、通信、能力、容量、可抢占条件、可达航路与能源，最后选择当时最低代价候选。每架记录首个未通过原因，不代表其他检查全部通过。

混合机队的航路项仅比较到当前任务点的风险A*代价，再按速度折算；能源预算包含后续任务与返场估计。混合代价不是实际到达秒数，无人机基准使用另一套代价，不能直接混比。全任务后续航段的能源估计不能视为精确可达保证。

左侧标记使用决策时的飞机位置。虚线是任务关联，实际规划航路仍为黄色。历史回放不会将飞机移回历史位置，也不回滚真实任务状态。

派单与资源放行是两个阶段。场站和大型航空器跨江航路独立约束容量；已有占用者继续执行，应急优先于等待者。结果页的资源快照标明决策时刻，现场上方显示当前占用情况。

## 样式与交互

- 下拉框统一箭头、边框、焦点、禁用状态，展开选项显式使用深色字和浅色背景，避免继承深色面板的浅色文字。
- 保留原生下拉框的键盘与触摸操作，长选项可通过提示查看完整文字。
- 机队行支持Tab聚焦、Enter或空格选中；起飞、爬升、降落、待命等阶段使用真实阶段描述。
- 展示控件按窗口宽度换行；窄屏不产生横向页面溢出。调度提示避开画面中部，保留主画面空间。

## 性能

仪表和属性仅在值变化时写入；候选行仅在内容变化时重建，事件排序按事件列表变化更新。暂停后，3D和2D停止无变化的重复绘制；拖拽、缩放、选机、后台航路结果、夜间和画质切换仍触发刷新。讲解图层跟随相机更新，无持续重建候选表。

切换城市视图时释放旧场景的几何、材质、纹理和WebGL上下文，断开ResizeObserver。决策记录有数量上限，每项保留初次检查与近期变化，重复轮询不无限堆积。

本轮性能原始采样在results/frontend-performance-before.json和frontend-performance-after.json。使用本机Chrome无头软件WebGL，每种状态采样5秒。CPU回调耗时不是GPU耗时或其他机器的帧率保证；沿用既有每帧计算预算，同样墙钟时间的仿真进度可能不同。

| 5秒本机采样 | 优化前 | 优化后 |
|---|---:|---:|
| 静止暂停时城市重复绘制 | 205次 | 0次 |
| 静止暂停时DOM变更 | 2970次 | 0次 |
| 4倍运行时DOM变更 | 3433次 | 1199次 |
| 调度回放暂停时城市重复绘制 | 196次 | 0次 |

运行中的4倍速CPU中位数均约1.7ms，本轮没有测出该指标的额外提升。主要收益是消除暂停与讲解时的冗余绘制和DOM变更，降低运行中界面更新量。
