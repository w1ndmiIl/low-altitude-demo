# 持续运营与机队规模

2026-10-13。当前默认保持16架无人机、2架直升机、2架eVTOL，共20架。

## 为什么暂不增加

原展示的稀疏状态主要来自巡逻/巡检只生成一批任务、讲解暂停整个城市。修复后，同样20架已能表现日常物流、巡逻、客运与突发应急同时运行，数量足够支撑课堂主线。

同一地面模型、种子42，运行1200仿真秒，无应急事件，从300秒起每50秒采样：

| 指标 | 原单次需求 | 持续运营 |
|---|---|---|
| 平均在空航空器（含返场及起降） | 5.05 | 14.84 |
| 平均执行业务的航空器 | 3.37 | 10.26 |
| 平均待命航空器 | 14.47 | 3.00 |
| 采样时日常待派数范围 | 0 | 3–9 |
| 1200秒累计日常完成 | 27 | 76 |
| 模型安全失败记录 | 0 | 0 |

数据：`results/continuous-fleet-study.json`；脚本：`tools/measure-continuous-fleet.cjs`。比较同时启用持续需求与局部优先协调，用于评估展示负荷，不是机队最优规模实验。待派任务受循环上限控制，数量受限不代表满足全部真实需求。Node计算耗时不是浏览器帧率或真实运力。

三架长期待命主要对应消防与直升机应急预留。没有需求时可以待命，不必为画面热闹强行给所有机型派日常任务。

## 优先级的边界

任务层按优先级与抢占条件派单；资源层优先排队但已有占用正常释放；局部飞行层检查任务优先级、5秒预测航段和高度间隔。不同高度或无冲突飞机不因出现应急任务全部停下。

局部让行只在当前位置能安全等待时采用。返航安全、起降净空和已载客限制仍优先。尚未实现完整多机时空预约、死锁消解或全局最优三维改线，不能把这次改动描述为这些能力。

## 何时再考虑增加

容量研究应先固定任务到达率和地图，再改变机队规模，测量等待、完成率、泊位/航路占用、持续饥饿和浏览器帧率。只有确认等待主要由航空器不足引起，而非单容量场站、能力或能源约束，再增加机队。

当前建议保持20架，优先保证持续运营、过程可解释和汇报电脑流畅。
