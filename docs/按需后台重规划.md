# 按需后台重规划

## 原因与修复

原实时执行把“世界版本改变”直接当作重规划条件。交通风险每3秒更新一次，使多架飞机同步运行A*。它们共享浏览器主线程，一架飞机的搜索也会阻塞其他飞机和画面。重新接入离散网格以及到达短航点后丢弃剩余时间步，还会造成运动顿挫。

浏览器现在默认采用按需后台执行。同步算法仍用于既有固定配置实验，便于复现原数据。

## 哪些变化需要改线

- 几何变化：检查自己的剩余航路。只有安全航段受到障碍影响才申请改线；其他航路保留。
- 风险变化：检查前方约300米至“巡航速度×12秒”的范围。加权风险增量峰值超过0.35、平均正增量超过0.1才申请择优；风险请求至少间隔12个仿真秒。
- 风险候选：当前航路仍安全时，新航路加权代价至少改善12%才采用，避免小幅车流变化造成反复摆动。
- 鸟群：保留同飞层、有限感知和2.2秒预测。提前请求后台绕行，只有紧邻约0.4秒内的运动段存在冲突时才避让等待。
- 静态无解：对几何版本、目标和位置相同的无解结果不重复搜索；位置、目标或障碍改变后重新检查。旧地图的失败结果不能锁死新地图。

阈值与时间窗口是课程参数，不属于真实飞行标准。逐步连续安全检测仍始终启用，未受影响的飞行不会因后台搜索而暂停。

## 计算与运动分离

demo/adaptive-planning.js创建本地Blob Web Worker，嵌入项目已有的A*与网格函数。无需联网或加载外部脚本。主线程仅提交城市版本快照、位置、目标、机型配置和预测点；后台处理搜索。

请求按返航、受阻/动态避障、初始航段、风险择优的优先级处理。重复请求合并。候选派单仍在主线程执行，但增加了同版本路径缓存和能源下界筛选，减少重复搜索。

规划计算期间保留安全旧航路。收到新结果后，从当前连续位置投影接入新路径，并重新检查连接段与路径的实际几何安全。任务切换、返航或重置后，旧目标的响应会被丢弃。

到达微小航点后继续消费当前0.05秒时间步的剩余部分，逐段检查安全和累计距离。没有瞬移、补发一大段积压位移或将计算延迟当作物理悬停。新任务尚无航路、现场服务、场站等待及真正无安全前缀时仍有合理的等待状态。

## 次数与数据口径

主屏“重规划”记录当前航段真正采用的新航路次数，初始航路与同路径结果不重复计入。悬浮该指标可查看后台请求次数；计算请求不等于改线次数。运营导出包含planningMode，单机实时汇总包含planning_requests、planning_accepted与planning_pending。

原202次配置试验及PPT中的对照图表对应固定同步基准。默认实时演示采用新的按需策略、连续航点推进和异步响应，因此路线、虚拟完成时间可能不同，也会受后台响应时机影响。不要把实时演示样例与旧表格混为同一组实验，或将二者差异直接归因于单个模块。

八套原浏览器流程在同步基准下回归；tests/browser-adaptive.cjs在固定巡航机队上单独验证后台模式，包括真实Worker、主线程A*调用为零、无影响更新不改线、计算期间继续运动、鸟群安全、650秒完整混合剧本及服务中断后的正确返航目标。该异步样例用于功能验证，不计入固定实验组数。tests/browser-ground.cjs另验证当前默认的地面起降、后台规划与完整1200s自动剧本。

## 验证

tests/adaptive.test.js包含11项针对性检查：无影响更新、连续接入、微航点推进、低收益拒绝、过期目标、新目标请求不被旧请求合并、请求合并、Worker与原A*固定图一致、真实安全等待、静态失败缓存和过期失败失效。完整结果见results/verification.json和output/playwright/adaptive-browser-check.json。
