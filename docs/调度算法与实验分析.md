# 多无人机调度与风险路径规划：技术分析

本文按实际源码说明计算机课程的技术主线。钱江世纪城两岸、配送、巡逻和救援用于生成异构任务与动态约束；调度、图搜索、连续几何、状态机和实验设计是主要研究内容。算法是课程工程实现，当前不保证多机全局最优。

## 1. 任务模型与评价目标

任务 `Tj` 包含 `type/priority/createdAt/waypoints/stage/state`，记录 `firstAssignedAt/arrivedAt/completedAt/interruptions/distance`。`priority >= 80` 为应急任务。没有截止期字段，因此不是 EDF 或实时系统截止期可行性求解。

飞机 `Ui` 包含能力集合 `skills`、连续位置、电量、飞层、当前任务与状态。八机具备不同能力，不能任意互换。飞层固定为 120–260 m，每机相差20 m；采用统一120 m保守障碍图，未实现同层冲突协调和动态升降。

研究目标是比较相同任务与约束下的派单等待、应急完成数量、逐任务响应和日常任务代价。当前没有把这些目标求成一个全局优化解，而是明确用队列顺序和候选代价实现贪心策略。

指标需要区分：

- 派单等待：首次派单时间减任务创建时间。
- 到位响应：到最终目标点时间减事件发布时间。
- 服务完成：到位后驻留、投放或记录结束。
- 跨江交接：空中物资服务完成 **且** 地面车辆到位。
- 风险暴露：`Σ R(position) × dt`，单位为风险值乘秒，不是真实事故概率。
- 观察窗未完成：JSON保留 `null`，CSV为空，不能改成零响应。

## 2. 调度策略与可复现伪代码

入口是 `demo/operations.js` 的 `dispatch`。每0.5个模拟秒调度，发布事件时也立即调度。界面可选择三种策略，源码通过 `policy` 与 `preemptionEnabled` 控制。

| 策略 | 队列顺序 | 在途日常任务抢占 |
|---|---|---|
| FIFO | 创建时间升序 | 关闭 |
| 优先不抢占 | 优先级降序，同级按创建时间 | 关闭 |
| 优先+抢占 | 优先级降序，同级按创建时间 | 开启，只允许应急抢占低优先级日常 |

```text
queue = queuedTasks.sort(policy)
for task in queue:
    best = null
    for actor in eligibleActors(task):
        route = A*(actorCurrentGrid, task.waypoints[task.stage])
        if route不存在: continue
        if remainingBattery < estimatedRequirement(route, task): continue
        score = route.cost * cellMeters + interruptionPenalty(actor)
        if score更小: best = actor
    if best存在:
        移除任务，保存被抢占任务，分配并启动新航段
    else:
        保持QUEUED，等待后续调度
```

候选飞机先按欧氏距离排序，但 **仍然检查全部符合条件的候选**，选择最小风险路径代价；不能把它描述成“取欧氏距离最近的一架”。每分配一项立即更新机队，再处理下一项，属于逐任务贪心。

### 2.1 候选筛选

任务类型必须在能力列表中；排除补能、停用、已返航飞机。常规候选为 `IDLE`；抢占候选必须同时满足：启用抢占、优先策略、当前任务为 `FLYING`、新任务为应急、原任务非应急且优先级较低。现场服务 `SERVICING` 不抢占。

电量先要求 `B > 35`，之后进行剩余任务预算。A*不能找到有效路线时也不能派单。电量高于35%只是初步条件，测试专门覆盖了“电量36%、当前和后续航段仍不足”的情况。

### 2.2 分配代价与能耗预算

候选代价为：

`Jij = 25 × C(A*ij) + 120 × I(actor.status == FLYING)`

`C(A*)` 是以格为长度基准的风险加权路径代价，乘25换成米量纲的等效代价；120表示抢占惩罚。这个参数不是测量得到的真实换单成本。

剩余任务航程预算为：

`Lhat = 当前A*路径几何长度(米) + 1.25 × 后续航点直线长度之和(米)`

`Bneed = Lhat × (0.008 + 0.035/12) + 20`

0.008是每米耗电百分点，0.035是每秒耗电百分点，12 m/s是标称速度，20是预留电量。后续段没有逐段精确A*，也未计载荷、风阻和真实返航需求，因此预算只是教学估计，不构成续航保证。现场服务与故障等待会继续耗电。

## 3. 抢占检查点与恢复

`assign` 将旧任务状态变为 `QUEUED`，`stage`不变，记录中断次数，把当前已飞距离计入旧任务与飞机总距离。新航段从当前位置开始，沿用当前电量和同一个 `HeartbeatLink` 对象。抢占不会使飞机瞬移、恢复100%电量或消除心跳历史。

旧任务再次被选中时，仍从保存的阶段执行，并重新检验能力、能耗与可达性。原任务可以由另一架有相应能力的飞机接手；本模型不保存实体货物的交接或携带约束，不能称完整物理货物恢复协议。航段导航异常和阵风等临时状态随新Simulation重建，不属于完整检查点。这是任务阶段恢复，尚非所有运行状态无损续接。

验证包含开关抢占对同一应急任务的行为差异、保留阶段、连续位置、电量及心跳对象身份。个人报告应展示自己实际复现的日志或代码，不把建议职责写成已完成贡献。

## 4. 风险A*：数据结构与正确性范围

源码 `demo/planner.js` 使用八邻域、二叉最小堆与 `Float64Array/Int32Array/Uint8Array` 保存 `g/parent/closed`。相同节点可能多次入堆，弹出时跳过过期或已关闭项。斜向移动要求相邻两个正交格均不阻塞，避免穿过障碍夹角。

边代价是：

`c(u,v) = d(u,v) × [1 + λg×(Rg(u)+Rg(v))/2 + λc×(Rc(u)+Rc(v))/2]`

`Rg/Rc` 是实际世界模型提供的非负归一代理场；默认权重3和2。权重为0退化为同图距离A*，负权重被拒绝。

几何octile启发式为：

`h = max(dx,dy) + (sqrt(2)-1)×min(dx,dy)`

八邻域几何距离本来满足一致性；当前非负风险使 `c>=d`，于是几何一致性不等式仍成立。障碍只会删边，不会引入更便宜的边。结论限于固定栅格和当前代价。动态预测占据、多阶段预算及多机贪心总体不因此获得全局最优保证。

`tests/core.test.js` 用20张小地图与独立Dijkstra参照比较最优代价，同时检查穿角、无路、负权重和连续接入。

算法出处：[Hart, Nilsson & Raphael, 1968](https://ai.stanford.edu/~nilsson/OnlinePubs-Nils/PublishedPapers/astar.pdf)。

## 5. 地图与动态环境算法

原始OSM在 `data/`，转换脚本为 `tools/prepare-qianjiang.py`。江南782栋、江北40栋抽样，共822栋；550个高度标签、272个补充高度。945条道路记录中56段有隧道标记，不是56条独立隧道。

局部经纬度投影为米坐标，再映射到256×144个25 m单元。高度加10 m达到120 m时纳入障碍。建筑足迹与单元相交检测，再保守外扩一格，覆盖比单元更小的高楼。更高飞层仍用120 m图，保守性牺牲部分通行效率。

路网保留节点、方向和道路边，车辆用 `length/speed` 作为Dijkstra代价；96辆常规车与专用跨江救护车按边、模拟信号和车距运行。固定地下深度由完整道路累计距离连续变化，防止每条短边都重新上浮。深度小于−1 m的车不直接叠加地面代理风险，入口地面排队仍参加统计。

鸟群只影响高度相近的飞层。90 m感知内读取理想轨迹，2.2 s预测窗口每0.2 s取样生成临时占据，预测冲突触发重规划或等待。不是图像检测或有噪声的轨迹估计。

### 连续相对线段最小距离

用两个小步端点定义：`r=a0-b0`，`v=(a1-a0)-(b1-b0)`。

`tau=clamp[-dot(r,v)/dot(v,v),0,1]`，`dmin=norm(r+tau*v)`。

`v=0`时距离恒定。用两物体半径之和检查相向交叉，避免仅检查帧末距离；建筑检查使用线段与膨胀矩形相交。公式精确对应当前步的线性近似，鸟的真实非线性运动未实现。高倍速仍切成不超过0.05 s的小步。

## 6. 共享时钟与版本化快照

`Operations.tick` 顺序推进公共时间和交通一次，再传播世界版本/占据缓存，逐机执行；子Simulation设置 `externalClock=true`。否则共享一个交通对象的8个子仿真可能把车流推进8次。

交通快照每3 s更新代理风险；几何/通信覆盖事件更新 `revision/lastChange/lastRisk`。每架飞机通过 `Object.create(masterWorld)`消费共享几何和风险，保留自己的高度、起终点、位置和心跳。程序是一个进程内的顺序模拟，没有真实网络分布式一致性协议。

初始多机界面暂停时也不提前推进公共车流，避免观察地图的时间改变任务试验起始状态。视角拖动与缩放不推进任务时钟。测试同时覆盖暂停、子飞机共享时间和浏览器初始车流时钟。

## 7. 安全与业务状态

飞行决策依次检查耗尽、返航锁定、新返航、短时失联、正常任务。心跳每0.5 s发送，年龄≥1.5 s悬停、≥4 s返航；电量≤20%返航，耗尽停止水平运动。恢复链路不能解除已触发的返航。

到航点之后进入现场服务，中间阶段服务3 s，最后阶段按任务配置计时，结束才算完成。返回家点后可以重新排队与简化补能；碰撞或耗尽停止标记失败。服务阶段检查能源、心跳和导航，异常时暂停、返航或停止。已接运人员的任务安全返航后标记ABORTED，不转派、不计完成人数；补能结束重建待命仿真，通信恢复后才可派单。

固定20 m飞层间隔提供结构性隔离，不能被称为同层避碰算法。固定基准的20s补能只恢复模型电量。当前实时模式已加入落地站点与垂直起降，但仍未模拟真实充电曲线或飞控动力学。

跨江完成守卫为 `airDeliveryCompleted && groundArrivedAt!==null && resolvedAt===null`。最后条件防止重复确认；空中未投放完或车未到时不得提前结束。这是单进程双支路AND汇合，不是分布式事务。

## 9. 复杂度、性能诊断与算法局限

`D=8`架飞机，`V=256×144=36864`格，八邻域 `E<=8V`。固定非负图的堆A*最坏可按 `O(V log V)`时间和 `O(V)`存储分析。`T`为本次队列长度，候选排序 `O(TD log D)`，调度总界为 `O(T log T + TD log D + TDV log V)`。D固定时候选排序可吸收进主要项。该界表示搜索工作量，不是实测毫秒时延。

新增诊断统计 `dispatchCalls/pathSearches/expandedNodes/unreachableRejected/energyRejected/assignments/maxQueue`，随运营JSON导出。仅计 `dispatch` 内的候选A*，不含飞行器自身动态重规划。

仅优先不抢占的seed42试验：1310次dispatch、626次候选搜索、694889个展开节点、602次搜索后电量预算拒绝、18次分配。大量重复预算拒绝表明存在优化空间。`node_wall_ms`包含地图初始化、交通、全部飞行器执行和调度，不应作为一次调度耗时或图形帧率。

尚未实现的改进：先用几何下界做能耗剪枝；按起终点和世界版本缓存路径；批量匹配或滚动时域优化；严格优先级增加老化避免日常饥饿；时间扩展图或同层冲突搜索。应明确区分已实现与后续计划。

## 11. 视角操作与接口隔离

3D默认左拖平移中心，按钮切换旋转，右键/Shift始终平移；滚轮缩放，点击画面后方向键平移，触摸支持双指平移与缩放。平移尺度由相机视野、距离和画布高度计算，并随镜头朝向转换到地面坐标。拖动退出跟随，防止每帧lerp把中心拉回无人机。恢复视角只重置相机，不重置任务。

2D采用缩放与平移变换，鼠标位置为缩放锚点；`hit`使用逆变换保持编辑格坐标正确。编辑模式左键仍是编辑，右拖平移；拖动超过阈值抑制点击编辑。窄屏按钮在3D内，兼容全屏。

实际浏览器验证包括平移、旋转、右拖、退出跟随、恢复、方向键、2D锚定缩放、2D恢复和原生双指输入。源文件为 `city3d.js/geo-city.js/view.js/app.js/style.css`。


## 12. 16机课堂展示模式

浏览器默认fleetSize=16，额外8架拥有独立身份、阶段、位置、电量与心跳，增加8条初始日常任务。可切回8机。固定对照明确使用8机，本文的实验表与D=8复杂度案例仍对应该基准。固定飞层每机20m，16机最高420m只作教学设定，不是实地飞行许可或高度建议。

3D按相机距离保持飞机和标牌可辨认，黄色圈标记当前选中对象，其他标牌重叠时隐藏部分文字但保留机体。选中航线、信息窗、定位与跟随相互对应。2D显示全队，缩放后的点选采用逆变换。下拉框为统一样式的原生select，保留键盘与禁用状态。


一屏演示入口：默认手动事件，点击主屏全屏即可集中展示操作、任务与城市画面。参数和详细数据下移，演示流程与状态解释见演示主屏说明.md。
