# 运行流畅性优化

本轮针对多机运行时的长停顿和3D绘制开销进行了优化，默认启用“流畅（自动）”画质。需要更清晰的画面时，在下方实验设置中将3D画质切换为“精细”。

## 已定位的开销

每次换航段原本会先创建一份完整钱江城市、道路交通和初始航路，随后再替换为共享世界。多架飞机同时结束取件时，这部分重复工作集中在同一帧。

此外，同一世界版本内，各飞机路径搜索重复计算大量相同栅格的风险与障碍。车辆、信号灯和机体由大量单独对象绘制，原默认场景约1600次绘制调用。交通风险变化还会触发不必要的几何与阴影重建。

## 实现

- 航段直接使用共享世界，只创建航空器自身的状态；不重复生成城市或无关初始航路。
- 对整数栅格风险和占据进行世界版本缓存。几何或风险变化后失效；连续位置的安全检测继续使用原函数。
- 车辆、信号灯、同类机体使用Three.js实例化批量绘制。机体矩阵与仿真位置一致，原有点选与跟随保留。
- 缓存城市静态阴影；动态小模型不逐帧重算投影。风险更新单独处理，几何变化才重建对应对象。
- 3D模式的小地图约每150ms刷新，使用简化底图。2D主视图仍逐帧更新，完整风险与参考航路可用。
- 飞机转向与跟随镜头采用平滑过渡。高倍率使用每帧计算预算，避免连续积压后突然跳跃；仿真仍按不超过0.05秒的小步检查安全。
- 流畅画质根据帧间隔调整3D分辨率，最低为视口的0.65倍；HTML仪表文字保持清晰。精细画质使用更高分辨率。浏览器图形能力不足时，实际加速低于目标倍率。

## 本机测量

环境为已安装Chrome的无头软件WebGL、1366×768、默认20架混合机队，各阶段测量约10秒。完整原始记录在results/performance-profile.json。

| 4倍速指标 | 优化前 | 优化后 |
|---|---:|---:|
| 单帧绘制调用，采样末帧 | 1610 | 147 |
| 主帧CPU耗时中位数 | 30.2ms | 6.9ms |
| 主帧CPU耗时95分位 | 152.6ms | 18.2ms |
| 主帧CPU耗时最大值 | 779.7ms | 46.4ms |
| 帧间隔中位数 | 133.3ms | 50.0ms |

实时预算和自动分辨率也是优化的一部分，因此相同墙钟时间内推进的仿真时间不同。上述为交互运行测量，不是严格同一模拟进度的微基准，也不代表所有电脑的帧率保证。

tests/performance.test.js核对缓存失效、只创建一次公共世界，以及既有8机两策略和20机优先策略seed42的全部汇总结果。tests/browser-performance.cjs核对实例矩阵、批量绘制、救护车、点选/跟随与画质切换。原模型测试和浏览器流程继续回归。
